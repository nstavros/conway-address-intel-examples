## Why this is a desktop job

Posting a comment requires being logged in as the account. The cloud container
has working egress (curl reaches instagram.com and youtube.com, HTTP 200) but a
headless Chromium with no cookies and no session. It can read public pages; it
cannot act as @empires.and.egos.

The previous posting path was the **Chatplace MCP connector**, which held stored
Instagram credentials and worked cloud-to-cloud with no browser. Nick cancelled
that service. Nothing has replaced it. So until a new connector exists, outbound
commenting runs through Claude in Chrome on the desktop, driving Nick's own
logged-in browser.

## Run it

1. **Find fresh posts by opening each profile grid directly.** Instagram hashtag
   pages and keyword search return *top* posts, not recent — everything found
   that way on 08-19 was 6+ months old and useless for first-comment advantage.
   The grid sorts newest-first. This is a documented finding; do not re-derive it.
2. **Draft one comment per post**, using `voice.reply_angles` from config:
   either *add a concrete sourced detail the post missed — an object, a number,
   a date*, or *pose the strongest historically-contested counterpoint as a
   question that invites argument*. Every fact from the bank above.
3. **Run the gates before posting.** With a `--backend-cmd` wired, `engage submit`
   gives the full stack including the LLM judge. Without one the judge fails
   closed and everything lands BLOCKED — that is by design, not a bug.
4. **Approve, then post via Claude in Chrome.** Approval binds to the text's
   SHA-256; editing after approval revokes it. Post the approved text verbatim.
5. **Record what was touched** so the 7-day cooldown stays honest.

Pace to account age, not to the rate limit. `rate_limits.instagram.replies_per_day`
is 10, but @empires.and.egos is 19 followers and three weeks old. Comment
*velocity* is what trips spam detection on new accounts, not raw volume. Four
good comments spread across the day beats ten in an hour.
